# ANOX — פלטפורמה לניהול ביצועי שחקני כדורגל (פיילוט)

פלטפורמת SaaS בעברית (RTL, מותאמת למובייל) לניהול סגל, היסטוריית אימונים ומשחקים ודוחות ביצועים, עם סביבה פרטית לכל קבוצה וחשבון מנהל פלטפורמה.

> זהו פיילוט עובד, לא מערכת מוכנה לפריסה מסחרית. ראו ״פער למוכנות מסחרית״ בסוף המסמך.

## הפעלה

### הדגמה מקומית (ללא שרת)
פתחו את `index.html` בדפדפן. נטענות שלוש קבוצות הדגמה עם 12 שבועות של נתונים מומצאים. כל השינויים נשמרים בזיכרון ונמחקים ברענון.

### מצב חשבונות (שרת)
דרישות: Python 3.9 ומעלה. אין תלויות חיצוניות.

```bash
python3 server.py create-owner   # פעם אחת: יצירת חשבון מנהל הפלטפורמה (אימייל, שם, סיסמה)
python3 server.py seed-demo      # רשות: שתי קבוצות הדגמה, מסומנות כהדגמה
python3 server.py                # http://127.0.0.1:8001
```

מסד הנתונים: `.local/anox.sqlite3` (לא נשמר ב-git). כניסה ללא התחברות מציגה את ההדגמה; כפתור ״כניסה לחשבון״ או הכתובת `/#login` פותחים את מסך ההתחברות.

משתני סביבה:

| משתנה | ברירת מחדל | תפקיד |
|---|---|---|
| `ANOX_PORT` / `ANOX_HOST` | `8001` / `127.0.0.1` | כתובת השרת |
| `ANOX_DB` | `.local/anox.sqlite3` | נתיב מסד הנתונים |
| `ANOX_SESSION_HOURS` | `12` | תוקף התחברות |
| `ANOX_COOKIE_SECURE` | כבוי | `1` מאחורי HTTPS — העוגייה תישלח רק ב-HTTPS |
| `ANOX_OWNER_EMAIL` / `ANOX_OWNER_NAME` / `ANOX_OWNER_PASSWORD` | — | יצירת מנהל פלטפורמה ללא שאלות (`create-owner`) |

### בדיקות
```bash
python3 -m unittest discover -s tests
```

## תפקידים והרשאות

| יכולת | מנהל פלטפורמה | מנהל קבוצה |
|---|---|---|
| יצירה, עריכה והשהיה של קבוצות; קביעת מסלול | ✓ | — |
| יצירת מנהלי קבוצה, השבתה, איפוס סיסמה | ✓ | — |
| יומן פעולות | ✓ | — |
| סגל, פעילויות, ייבוא/ייצוא, מכשירים | כל הקבוצות | הקבוצה שלו בלבד |
| שינוי סיסמה עצמית | ✓ | ✓ (חובה בכניסה הראשונה) |

ההפרדה נאכפת בשרת בכל בקשה: כל נתיב תחת `/api/teams/{id}/…` עובר בדיקת גישה, וכל מזהה שחקן, פעילות, ייבוא או מכשיר נבדק כשייך לאותה קבוצה. מנהל שמנסה לגשת לקבוצה אחרת מקבל 404 (בלי לחשוף שהיא קיימת). קבוצה מושהית חוסמת את מנהליה ומנתקת את החיבורים שלהם.

## מקור הנתונים

כל פעילות נושאת שדה `source` שאינו ניתן לשינוי, ומוצג בכל מסך:

| מקור | משמעות | איך נוצר |
|---|---|---|
| `demo` — הדגמה | נתונים מומצאים | רק `seed-demo` או מצב ההדגמה; קבוצות הדגמה מסומנות גם ברמת הקבוצה |
| `manual` — הזנה ידנית | הוקלד בממשק | מסך ״הזנת פעילות״ |
| `csv` — ייבוא CSV | יובא מקובץ | מסך ״ייבוא וייצוא״, עם רשומת ייבוא שניתן לבטל |
| `device` — מכשיר | הגיע מהמכשיר או מהאפליקציה | **שמור בלבד. אין חיבור כזה כרגע**; ה-API אינו מקבל ערך זה מהלקוח |

## מודל הנתונים

`teams` ← `players` ← `activity_metrics` → `activities` → `import_batches`

- **activities**: תאריך, סוג (אימון/משחק), כותרת, מקור.
- **activity_metrics**: שורה אחת לשחקן בפעילות — מרחק (ק״מ), מהירות שיא (קמ״ש), ספרינטים, דקות. כל ערך יכול להיות ריק; ריק אינו אפס.
- **devices** + **device_assignments**: רישום מכשירים ושיוך לשחקן, עם היסטוריה. מכשיר אחד לשחקן אחד בכל רגע (נאכף במסד הנתונים).
- **audit_log**: יומן של כל פעולה משנה.
- שחקן אינו נמחק: הוא מועבר לארכיון, וההיסטוריה שלו נשמרת.

## מדדים ודוחות

- **סקירת קבוצה**: פעילויות, מרחק ממוצע לשחקן בפעילות, מהירות שיא, עצימות (מטר לדקה), ספרינטים, השוואה לתקופה הקודמת, גרף לפי פעילות ומובילים.
- **דוח שחקן**: מגמות, השוואה לממוצע העמדה, היסטוריה מלאה עם מקור לכל שורה, הדפסה או שמירה כ-PDF.
- **השוואת שחקנים**: עד ארבעה שחקנים, מול ממוצע הקבוצה.
- תקופות: 7, 30 או 90 ימים, או כל התקופה.

עצימות = סך המרחק ÷ סך הדקות, רק בשורות שבהן הוזנו שני הערכים. ספרינטים מחושבים רק בפעילויות שבהן הוזנו. **לא אומת שהמכשיר מפיק נתון ספרינטים.**

## ייבוא CSV (דרך הזנה זמנית)

```
date,type,title,name,position,number,distance,speed,sprints,minutes
2026-10-10,match,משחק ליגה,ישראל ישראלי,MID,8,10.4,30.2,17,90
```

- חובה: `name, distance, speed, minutes`. הכותרות מתקבלות גם בעברית.
- הפורמט הקודם (`name,position,number,distance,speed,sprints,minutes`) עדיין נתמך. התאריך והסוג נלקחים מהטופס.
- התאמת שחקן: לפי מספר חולצה, ואם אין — לפי שם מלא. אי־התאמה בין שם למספר נחשבת שגיאה.
- הקובץ נבדק לפני השמירה. אם יש שגיאה אחת לפחות, דבר אינו נשמר. ייבוא חוזר של אותה פעילות מציג אזהרה.
- **שינוי התנהגות מהפיילוט הקודם:** ייבוא מוסיף פעילויות להיסטוריה ואינו מחליף את הסגל. כל ייבוא ניתן לביטול.
- ייצוא: כל ההיסטוריה, כולל עמודת `source`, בקידוד UTF-8 עם BOM כדי שהקובץ ייפתח נכון ב-Excel.

## אבטחה במצב הנוכחי

- סיסמאות: PBKDF2-SHA256 עם 310,000 איטרציות ו-salt אקראי. אורך מינימלי של 10 תווים. סיסמה זמנית מחייבת החלפה.
- סשן: טוקן אקראי שנשמר כ-hash בלבד, בעוגיית HttpOnly עם SameSite=Strict ותוקף מוגבל. איפוס סיסמה, השבתה או השהיה מנתקים את המשתמש.
- CSRF: כל בקשה משנה חייבת לכלול את הכותרת `X-ANOX-Request`. בשילוב עם SameSite=Strict, בקשה מאתר זר נחסמת.
- הגבלת התחברות: 5 כישלונות לאימייל או 20 לכתובת IP ב-15 דקות.
- כותרות אבטחה: CSP, nosniff, frame-ancestors none. השרת מגיש רשימה סגורה של קבצים סטטיים בלבד, כך שאין גישה למסד הנתונים או לקוד.
- כל פעולה משנה נרשמת ביומן.

## החיבור למכשיר

ראו [docs/device-integration.md](docs/device-integration.md). בקצרה: כל כתיבת נתונים עוברת בפונקציה אחת, `ingest_activity()` ב-`server.py`. מתאם עתידי למכשיר יפיק פעילויות במקור `device` דרך אותה פונקציה, וישייך כל הקלטה לשחקן לפי טבלת שיוך המכשירים. עד לקבלת תשובה מהספק לא מומש מתאם, ולא מוצגים מסלולים, מפות חום או מעקב חי.
