# חיבור מכשיר ANOX (AT01) — תכנון

## מה ידוע (ממדריך הספק ומדף המוצר)

- דגם: Action Tracer AT01 / AT‑01, יצרן Sibo Technology (Zhuhai) Co., Ltd. השם queling מופיע בדף המכירה, אך הקשר שלו ליצרן לא אומת.
- המכשיר מקליט GPS בלי חיבור רציף, ומסתנכרן לאפליקציה לצורך שיוך שחקן והעברת נתונים.
- משויך לשחקן אחד בכל רגע.
- האפליקציה מציגה מרחק, מהירות מרבית, קלוריות, מפות חום, מסלולים ושחזור פעילות.
- הקלטה של עד 2.5 שעות ועד 15 מקטעים; נתונים חדשים עשויים לדרוס ישנים.
- ״עד 8 שעות סוללה״ בדף המכירה אינו מעיד על 8 שעות הקלטה.

## מה לא ידוע (ולכן לא מומש)

שם האפליקציה, ייצוא קבצים (CSV/GPX/FIT), API או SDK, גישה של כמה טלפונים בו־זמנית, מעקב חי, ונתון ספרינטים מהמכשיר. אי־אפשר לגשת לאתרי הספק מסביבת הפיתוח, ואין להסיק מכך שאין API.

## מה כבר מוכן במערכת

1. **נקודת כתיבה אחת**: `ingest_activity(conn, team_id, date_=…, kind=…, title=…, source="device", metrics=[…], import_batch_id=…)` ב-`server.py`. כל המסכים והדוחות כבר מציגים נתונים במקור `device`, עם תווית ״מכשיר״.
2. **רשומת ייבוא** (`import_batches.source = 'device'`): כל סנכרון יירשם כאצווה, ואפשר לבטל אותה כמו ייבוא CSV.
3. **רישום מכשירים ושיוך היסטורי** (`devices`, `device_assignments`): לכל הקלטה אפשר לדעת איזה שחקן החזיק במכשיר בזמן ההקלטה.

## מתאם עתידי — חוזה

מתאם (קובץ חדש, לדוגמה `adapters/at01.py`) יקבל קלט מהספק ויחזיר רשימת הקלטות:

```
DeviceRecording:
  device_serial | device_label   — זיהוי המכשיר
  started_at, ended_at           — זמנים (UTC)
  distance_km, max_speed_kmh     — רק אם המקור מספק אותם
  sprints                        — None אם לא סופק. אין לחשב ממהירות בלי הגדרת סף מתועדת
  minutes                        — משך ההקלטה
  track                          — נקודות GPS גולמיות, אם קיימות (לשמירה עתידית)
```

תהליך הקליטה:
1. איתור המכשיר לפי מספר סידורי או תווית בקבוצה. מכשיר לא מוכר נדחה עם הודעה, ולא נוצר אוטומטית.
2. איתור השחקן לפי `device_assignments`, בשיוך שהיה פתוח ב-`started_at`.
3. קיבוץ הקלטות לפעילות לפי תאריך ובחירת המנהל (אימון או משחק).
4. כתיבה דרך `ingest_activity(source="device")` תחת אצוות `import_batches(source='device')`.
5. שמירת קובץ המקור הגולמי לצורך ביקורת.

נתוני מסלול ומפות חום יחייבו טבלה נוספת (`activity_tracks`: ‏metric_id, format, path), ותצוגה על גבי מפת מגרש. נבנה אותן רק כשיהיה מקור נתונים אמיתי לבדיקה.

## שאלות לספק (לשליחה חוזרת)

1. מה שם האפליקציה הרשמית (iOS/Android), ומי מפרסם אותה?
2. האם יש ייצוא נתוני אימון מהאפליקציה? באילו פורמטים (CSV, GPX, FIT, TCX)? נשמח לקובץ לדוגמה.
3. האם קיים API בענן או SDK (BLE) לקריאת נתונים מהמכשיר? באילו תנאים, ומה העלות?
4. אילו שדות נשמרים לכל הקלטה: נקודות GPS עם חותמת זמן, תדירות דגימה, מרחק, מהירות, ספרינטים (ואיך מוגדרים), קלוריות?
5. האם מכשיר מזוהה במספר סידורי שנגיש לאפליקציה או ל-SDK?
6. האם כמה טלפונים יכולים לסנכרן מכשירים של אותה קבוצה? האם יש חשבון מאמן מרכזי?
7. מה קורה כשמגיעים ל-15 מקטעים או ל-2.5 שעות: האם הנתונים הישנים נדרסים?
8. האם יש אפשרות למיתוג פרטי (white label) של האפליקציה?
